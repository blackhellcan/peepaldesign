    Inside the GapScan engine

    1. Collect. Reads pasted code and public HTTPS pages. Documentation traversal stays within the input path; public GitHub repositories use the source tree. Scans have page, size, and time budgets.
    2. Extract. Inventories CSS/Sass and JSON tokens, CSS selectors, component exports, typed APIs, documentation headings, and HTML/JSX examples. There is no fixed component count.
    3. Filter. Removes supporting headings, documentation chrome, metadata, and archived/test sources. Runtime examples inside guides stay in scope; excluded observations remain in the audit ledger.
    4. Match. Normalizes identifiers and known naming aliases, then compares observed values. Suggested token-family mappings need review.
    5. Show evidence. Every card has source snippets. Runnable HTML/CSS is isolated in a sandbox; Original variants, SVG icons, styles, fonts, and versioned component runtimes appear in source and target galleries. Where a runnable example is unavailable, its documentation can be opened. Additional files are optional.
    6. Plan. Estimates use visible heuristics and editable per-application hours. Export a JSON, standalone HTML report, or Markdown technical specification.

    The engine is deterministic, not a Gemini service. It cannot read authenticated/private sources or reconstruct arbitrary React/Angular applications from documentation links. Source-only means no counterpart was found in the scanned content, not confirmed removal. Results need manual review for semantic equivalence and architectural changes.
